  - Design the real-time system to support up to 500,000 concurrent users with efficient fan-out.
  - Support per-subscription channels in the real-time layer (subscribe by match and by competition).
  - Implement robust reconnection logic for WebSocket clients to resume subscriptions cleanly after disconnects.
  - Target 99.9% availability for the real-time system during match hours.
  - Develop the public website using React/Next.js with server-side rendering so match and team pages are indexable by search engines.
  - Make the website responsive, performant, and multilingual (Spanish and English) from launch.
  - Implement per-match pages on the website with live score, lineups, statistics, and an event feed.
  - Generate sitemaps and structured data (schema.org or equivalent) for match and team pages to support rich snippets.
  - Design for good Core Web Vitals (fast loading, interactivity, visual stability) for the public site.
  - Deliver mobile apps for iOS and Android from a single codebase (React Native or Flutter).
  - Include the same Match Center experience in the mobile apps as on the web.
  - Implement favorites management in web and mobile and synchronize favorites across devices when users are logged in.
  - Implement push notifications for goals and other events, delivered via APNs and FCM.
  - Support background push notifications so users receive alerts even if the app is not open when they follow a team.
  - Provide offline support in the mobile apps to show the last cached data when there is no network.
  - Support deep links that open a specific match in the app from notifications or from the web.
  - Build an in-house notification service that uses FCM and APNs and supports segmentation by favorite team/competition.
  - Notification service must support quiet hours/preferences, campaign messages, measurement of opens, and ad-hoc campaign sends (e.g., “match starting” broadcasts).
  - Provide webhook/events and metrics for notification deliveries and opens for marketing and analytics.
  - Provide an internal backoffice UI for operations to correct provider data (match results, goal scorers, match time changes) manually.
  - Backoffice must allow management of competitions, teams, team badges/escudos, and editorial home pages.
  - Implement role-based access control in the backoffice and an audit log/historical record of all changes.
  - Support user accounts with registration and login via email, Google Sign-In, and Sign in with Apple.
  - Provide user profiles with favorites management and account deletion that complies with GDPR.
  - Implement explicit consent capture and storage for push notifications and other GDPR-relevant actions.
  - Support a monetization model with ad-supported free tier and a paid subscription that removes ads, enables advanced statistics, and enables unlimited alerts.
  - Integrate Stripe for web payments and implement platform-compliant in-app purchases for iOS and Android.
  - Implement subscription management: plans, coupons, trial periods, and webhooks for renewals and cancellations.
  - Ensure premium/subscription state is reflected in web and mobile clients in real time without requiring a full page/app reload.
  - Host infrastructure in cloud with autoscaling, CDN for static assets and cached pages, and infrastructure-as-code.
  - Design event ingestion queues and WebSocket/fan-out infrastructure to scale independently from the rest of the system.
  - Implement observability: metrics for ingestion rate, event-to-screen latency, API latencies and errors, and alerting.
  - Implement public API rate limiting and protections against aggressive scraping.
  - Emit product analytics events (matches viewed, favorites set, notifications opened, conversion to premium) and provide an internal dashboard for product and marketing.
  - Respect data provider contractual limits on what can be exposed in the public API and include required attribution metadata.
  - Use PostgreSQL as the relational database and Redis for cache and pub/sub in the reference architecture.
  - Prefer Node.js and React for web/backend stack given internal team skills; mobile tech (React Native or Flutter) to be decided during implementation.
